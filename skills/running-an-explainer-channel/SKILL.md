# Running an explainer channel

## Overview
A channel is a production line: one fact-checked script, one consistent voice, one code-drawn animation, one QA pass, then a release at the same minute on every platform. Each stage has its own skill. This skill covers the order, what "done" means at each stage, and the decisions you make only once.

## Stages
| # | Stage | Skill | Done when |
|---|---|---|---|
| 1 | Hook and script | scripting-explainer-shorts | The hook is verified true; 125–148 words; every claim has a source row |
| 2 | Voice and captions | voicing-and-captioning-shorts | Narration at −14 LUFS; word timings checked against the script; caption spec built |
| 3 | Animation and render | animating-shorts-in-hyperframes | `check` has 0 errors; frames reviewed twice; render verified |
| 4 | Release | publishing-shorts | Scheduled on every platform and the site for one release time; logged |

## Decide once, before episode 1
1. **Format name = title pattern.** For example "Behind the ___" or "Inside the ___". It is searchable, repeatable, and builds recall.
2. **Niche.** Explain real, everyday things. Avoid saturated speculative formats ("What if…"), which compete on volume rather than trust.
3. **Look.** Write it as numbers in the project's `DESIGN.md`: palette with roles, two fonts, safe zones, motion timings, and a what-not-to-do list. Start from `animating-shorts-in-hyperframes/template/DESIGN.example.md`. The look is the moat, so keep it consistent.
4. **Voice and music.** Pick one narrator voice and one music bed and reuse both in every episode.
5. **Pilot gate.** Make one episode and get the owner's explicit approval of the voice, the captions and the first 2 seconds before making more.

## Producing a batch
- Give each episode one subagent, which owns stages 1–3 in its own folder.
- The brief is the topic, the release date, the paths to these skills and the project's `DESIGN.md`. If an agent needs more than that, the skill has a gap: fix the skill, not the brief.
- Ask every agent for a short report: the render path, its duration and loudness, the hook, and any claim it could only partly verify.
- Review every render yourself (the contact sheet, plus a look at the hook frame) before scheduling it. "Check passed" is not a review.

## Accounts
- **Never create accounts or type passwords**, even when asked. Give the owner the exact values (name, handle, bio) and let them sign up or sign in, then do the rest: profile, uploads, scheduling.
- Check a handle on every platform before committing to it. See publishing-shorts.

## Common mistakes
| Mistake | Fix |
|---|---|
| Making episodes 2–4 before the pilot is approved | Stop at one; get explicit sign-off |
| Trusting a subagent's summary | Open its review sheet or render yourself |
| A brand handle free on one platform, taken on another | Check all platforms first |
| Releasing platform by platform | Use one release time and schedule everything |
| Adding facts in descriptions or site copy | Copy only claims that are already in the episode's sources |
